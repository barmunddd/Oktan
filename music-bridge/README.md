# Spotify / OKTAN

Это локальный контроллер Spotify Connect. Музыку воспроизводит Spotify на выбранном компьютере; в Roblox звук не передаётся. Клиент умеет искать треки по исполнителю, группе и названию, выбирать ПК, запускать, приостанавливать и останавливать воспроизведение. Stop означает Pause и сброс позиции на начало.

## Подключение один раз на запуск модуля

1. В настройках своего приложения [Spotify Developer Dashboard](https://developer.spotify.com/dashboard) добавь **Redirect URI**:

   `http://127.0.0.1:8974/callback`

2. В PowerShell запусти (вместо `ТВОЙ_CLIENT_ID` подставь Client ID своего приложения, не Client Secret):

   ```powershell
   python "C:\Users\Ssweur\Documents\ChatGPT\oktan-client\music-bridge\spotify_bridge.py" --client-id "ТВОЙ_CLIENT_ID"
   ```

   Для другого компьютера укажи свой путь к `spotify_bridge.py`. Требуется Python 3.9+; дополнительных пакетов нет. Для другого исполнителя добавь `--workspace "ПУТЬ_К_WORKSPACE"`. По умолчанию используется `%LOCALAPPDATA%\Xeno\workspace`.

3. Открой Spotify на своём ПК. В OKTAN открой **Settings → Music → Spotify → Connect**. Клиент откроет страницу входа или скопирует ссылку, если исполнитель не умеет открывать браузер. Вход и подтверждение доступа выполни самостоятельно.
4. Нажми **Devices** и выбери свой ПК. При пустом списке включи трек один раз в приложении Spotify и повтори Devices.
5. Введи группу, исполнителя или песню → **Search** → нажми найденный трек. **Play** продолжает текущий трек, **Pause** ставит на паузу, **Stop** сбрасывает позицию.

Оставь окно Python открытым. `Ctrl+C` завершает модуль и удаляет его pairing-файл; текущую музыку в Spotify это не останавливает. При выгрузке клиента Spotify также остаётся под твоим управлением. Сохранённый конфиг не запускает музыку автоматически.

## Ограничения Spotify

Для управления воспроизведением через Web API нужен Spotify Premium. Приложения в Development Mode имеют ограничения пользователей, доступов и квот; для покупателей нельзя обещать неограниченное подключение через один тестовый Client ID. Аккаунт должен быть допущен к приложению согласно текущим правилам Spotify. Пока Client ID и вход не предоставлены, проверены только имитации API, не реальное воспроизведение аккаунта.

Источники: [Playback](https://developer.spotify.com/documentation/web-api/reference/start-a-users-playback), [Quota modes](https://developer.spotify.com/documentation/web-api/concepts/quota-modes), [PKCE](https://developer.spotify.com/documentation/web-api/tutorials/code-pkce-flow).

## Данные и доступ

OAuth работает через PKCE, без Client Secret. Токены Spotify хранятся только в памяти локального процесса. В workspace записывается отдельный случайный pairing-токен для доступа клиента к `127.0.0.1:8974`; его нельзя публиковать или пересылать. Сервис не слушает внешний интерфейс, проверяет Host и pairing-заголовок, отвергает запросы от веб-страниц. Поиск запускается только пользователем; статус запрашивается не чаще раза в 10 секунд при открытой панели. Ошибки 429 учитывают Retry-After. История поиска и OAuth-токены на диск не пишутся.
